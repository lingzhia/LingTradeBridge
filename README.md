# LingTradeBridge

LingTradeBridge 是 LingQuant 的**交易信号跟单桥**：接收外部策略产生的交易信号，并将信号转换为交易客户端可以执行的操作。

它位于“策略信号”和“交易客户端”之间，不负责完整的策略研究、金融数据基础设施或策略运行引擎。

## 在系统中的位置

```text
外部策略或策略运行环境
          │
          │ 交易信号
          ▼
   ┌───────────────┐
   │ LingTradeBridge│
   │   信号跟单桥    │
   └───────┬───────┘
           │
           │ 交易客户端操作
           ▼
       同花顺等交易客户端
```

## 主要职责

- 接收外部策略发送的交易信号。
- 对信号进行接收和转换。
- 将交易信号交给交易客户端执行。
- 提供跟单运行界面、配置和运行日志。
- 保存跟单相关的本地状态和记录。

## 目录说明

- 项目根目录：跟单器本体（主程序、HTTP 服务、下单执行器、仓位管理器），是这套东西的核心。
- `tools/`：**附加内容**，放在策略侧（如聚宽研究环境）运行的信号发送库，跟单器本体不依赖它，可以单独拷走使用。
- `启动跟单器.app`：必须与 `同花顺跟单器_mac.py` 同目录（靠相对位置定位项目），不要单独拖到别处。

## 信号来源

当前项目代码包含两种信号接收方式，由配置项 `signal_source` 统一控制：

- `http`（默认）：只启用本地 HTTP 信号服务，通过 `POST /signal` 接收信号，无需 Redis。
- `redis`：只从配置的 Redis 通道接收实时信号。
- `both`：两者同时启用。

HTTP 服务提供以下接口，除 `/health` 和 `/` 外都需要 Token 鉴权（请求带 `Authorization: Bearer <token>`），且默认只绑定 `127.0.0.1`。

> **把 `HTTP地址` 改成 `0.0.0.0` 就等于对局域网开放**：同一个网络里任何设备都能访问这几个接口（包括读你的持仓/委托/成交），启动时日志会打一条 WARN 提醒。这样用之前请务必把 `HTTP Token` 从内置默认值改成一串自己的随机字符；另外这是纯 HTTP，Token 在网络上是明文传输的，不要做公网端口映射。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查（免鉴权） |
| GET | `/` | 端点列表（免鉴权，机器可读） |
| POST | `/signal` | 接收交易信号 |
| GET | `/account` | 资金明细（总资产/可用金额/可取金额…） |
| GET | `/positions` | 持仓（读同花顺界面表格） |
| GET | `/orders` | 委托 |
| GET | `/deals` | 成交 |

四个查询接口都是**读同花顺客户端界面上正在显示的表格**（走 macOS 辅助功能），不是查跟单器自己的台账，因此需要同花顺处于运行且停在交易界面的状态；读不到时返回 `503`。`/positions`、`/orders`、`/deals` 共用同一个表格控件，查询时会自动切换页签，所以它们返回的内容与界面上当前显示的页签会互相影响。

返回结构：`/account` 为 `{"account": {"总资产": 148458.38, ...}}`；其余三个为 `{"headers": [...], "rows": [{"列头": 值, ...}, ...]}`。

数值按字段语义归一——数量取整、价格 3 位小数、金额 2 位小数、比例(%) 3 位小数；空值和 `-` 之类占位符统一为 `null`；证券代码/名称/编号/日期时间等保持字符串（避免 `000001` 丢掉前导零）；无法识别的字段原样返回字符串。`/account` 中值为空的按钮行（风险测评/银证转账/账户设置）会被丢弃。

Token 取自配置项 `http_api_token`，项目内置了一个默认值，开箱即可使用；建议在 `网页跟单配置.json` 或界面「HTTP Token」里改成自己的值，并同步给发送信号的一方。具体信号字段、配置项和执行规则以当前代码及配置文件为准。

## 启动

macOS 下有两种入口，日常用 `.app`，需要看输出时用 `.command`：

```bash
open 启动跟单器.app          # 双击也行: 不弹终端窗口, 直接显示界面
./启动跟单器.command          # 保留终端窗口, 能实时看到日志输出
```

`.command` 还支持指定本次运行的信号源：

```bash
cd LingTradeBridge
./启动跟单器.command          # 用配置文件里的信号源（默认 http）
./启动跟单器.command http     # 本次只用 HTTP
./启动跟单器.command redis    # 本次只用 Redis
./启动跟单器.command both     # 本次 HTTP + Redis
```

启动脚本会优先使用项目目录下的 `.venv/bin/python`，否则使用 `python3`。命令行参数只影响本次运行，不会改写 `网页跟单配置.json`；想永久切换请在界面「信号源」下拉框里选好后点[保存配置]。`.app` 无法传参，一律按配置文件里的 `signal_source` 启动。

`.app` 的输出写在 `logs/启动器_YYYY-MM-DD.log`，运行日志仍然是 `logs/运行日志_YYYY-MM-DD.txt`。

### 辅助功能权限（换用 .app 后必须重新授权一次）

macOS 按「谁启动的」记录辅助功能权限：以前从终端启动，权限记在终端头上；现在改用 `.app` 启动，记账对象变成了这个 `.app`，**必须重新授权一次**，否则读持仓/委托和下单都会被系统拒绝。

首次双击 `.app` 后程序会自动弹出系统授权窗口，点「打开系统设置」，在「隐私与安全性 → 辅助功能」里把「同花顺跟单器」勾上即可 —— 授权是**立即生效**的，不用重启程序，回来点[测试]就能验证。（也可以手动把项目里的 `启动跟单器.app` 拖进那个列表。用 `.command` 启动则沿用终端原有的授权。）

Redis 跟单还需要准备对应的 Python 依赖和 Redis 服务。

## 配置的保存与生效时机

界面上一改东西，顶栏按钮就会变成蓝色「保存配置 ●」，表示还没写盘；点一下即保存到 `网页跟单配置.json`。

| 情况 | 生效范围 |
|---|---|
| 点[保存配置] | 跟单规则（比例、过滤开关、最小下单量、买二卖二等）对**之后每一笔**信号立即生效 |
| 点[开始跟单] | 先把界面上的改动收进来（未保存的会顺带写入配置文件），再启动通道；**监听参数**（信号源、HTTP 端口、Redis 地址/通道等）在这次开始跟单时生效 |
| 跟单进行中 | 左侧配置区（① 同花顺客户端 / ② 信号源 / ③ 跟单规则）整体锁定不可编辑，停[停止跟单]后自动解锁 |
| 跟单进行中改监听参数 | 要[停止跟单]再[开始跟单]才生效 |
| 关窗口时还有未保存改动 | 会弹确认，不确认就退出会丢掉改动 |

区分两类参数：跟单比例、过滤开关这类是**每笔信号现读现用**，保存后立刻生效；HTTP 端口、Redis 连接这类只在**启动通道那一刻**读一次，改完必须重启一次跟单通道。（程序里那些自动操作，比如盘前强制关闭「允许回测信号实盘下单」，不会误触发未保存提示。）

## 与其他子项目的关系

| 项目 | 关系 |
|---|---|
| `LingStrategies` | 提供策略代码和研究资料；本项目不负责策略研究。 |
| `LingRun` | 提供本地策略运行能力；本项目是独立的信号接收与跟单路径。 |

本项目 README 只说明系统职责和使用入口，不将某一条信号来源或交易路径定义为整个 LingQuant 的统一生产流程。
